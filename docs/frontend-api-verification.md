# API 정합성 검증 기록

관련 이슈는 [#614](https://github.com/UMC-DISPLAYU/Backend/issues/614)이며 검증일은 2026-11-15입니다. API 입력·응답과 호환 정책은 [계약 문서](frontend-api-alignment.md)에 정리했습니다.

## 전체 자동화 테스트

JDK 21에서 CI와 동일하게 `./gradlew spotlessCheck clean build --no-daemon`을 실행했습니다. 기능별 통합 뒤 전체 검증을 실행하고 커밋했습니다. 전체 구현 통합 시 1,324개 테스트가 모두 통과했으며 실패·오류·스킵은 0개입니다. 실행 JAR에 마이그레이션 91개가 포함된 것도 확인했습니다.

| 범위 | 주요 검증 |
| --- | --- |
| 분야 | 12개 작가 생성·조회·수정, 작품 저장 후 조회, JSON/쿼리 별칭, 기존 값 유지와 신규 선택 거절, 작품 3개 허용·4개 거절 |
| 검색·지도 | 학교·세부 소속 검색, 좋아요 동률·0개·취소·복합 커서, 지도 날짜·좌표 경계, 전체 조회 101개 |
| 팀원 | 기본 닉네임과 초대 ID, 권한·재취소·재초대, 수락/취소 동시 요청에서 하나만 성공하고 최종 팀원 상태 일치 |
| 섹션 | 전체 순서 저장 후 상세 재조회, 중복·누락·타 전시 거절, 사진 포함 생성과 실패 시 무변경, 기존 빈 섹션 생성 |
| 작품 조회 | 공동 작가 ID와 Q&A 전용 계정 제외, 제목·대표/공동 작가 검색, 부모 공개·삭제·기간, 인접 페이지 경계 |
| 추천 | 최초 공개일 우선, 필터 후 전시 순위, 순환·소진·단일 전시 채움·10개 제한·동률, 재공개 시각 보존 |

분야·초대·섹션·검색, 작품 크롭·칼럼, 작품 추천·공개 흐름을 나누어 독립 코드 리뷰를 진행했습니다. 수정이 필요한 추가 결함은 발견하지 못했습니다. 주석 리뷰에서 확인한 중복·부정확한 주석 2개와 신규 테스트의 사용하지 않는 보조 코드를 정리했습니다.

## 실제 MySQL

기존 로컬 MySQL 8.4 이미지를 재사용했습니다. 태그 상세 조회가 실패하여 목록과 이미지 ID로 동일 이미지를 확인한 후 `--pull=never`로 별도 컨테이너를 실행했습니다. 기존 컨테이너·이미지·저장 볼륨은 변경하지 않았습니다.

- 기존 마이그레이션 85개 적용 후 과거 분야·공개 작품·초안·대기 초대 데이터를 삽입했습니다.
- 신규 6개 적용 후 `MEDIA`, `DESIGN`, `UXUI`의 원본 값 보존과 신규 12개 enum 저장을 확인했습니다.
- 공개 작품은 `createdAt`으로 최초 공개 시각을 이관하고 초안은 null로 남는지 확인했습니다.
- 재료 NULL, 취소된 초대의 생성 열 해제, 재초대 성공과 중복 대기 초대 거절을 확인했습니다.
- 작품·칼럼 크롭의 `DECIMAL(11,10)`과 정확한 소수점 왕복을 확인했습니다.
- Hibernate의 전체 엔티티 74개 스키마 검증을 통과했습니다.
- 실제 전시 검색 adapter를 `ONLY_FULL_GROUP_BY`에서 실행했습니다. 좋아요 동률·0개 다음 페이지와 과거 분야 별칭 검색을 확인했습니다.
- 실제 지도 adapter의 전체 결과와 종료 전시 제외, 작품 검색 adapter의 필터·페이지 경계를 확인했습니다.
- 실제 native 추천 SQL로 순환 순서·소진·별칭 AND 조건·단일 전시 10개 제한을 확인했습니다.
- 실제 일괄 공개 JPQL 두 경로를 실행해 최초 시각의 마이크로초 정밀도와 재처리 시 보존을 확인했습니다.
- Flyway 체크섬 검증을 통과했으며 재실행은 추가 적용 0개였습니다.

검증 컨테이너와 해당 임시 볼륨을 제거했고 태스크 컨테이너가 남지 않았음을 확인했습니다.

## 실제 HEIC 업로드

HEIC 미지원 테스트 2개가 수정 전에 실패하는 것을 확인한 뒤 허용 목록을 변경했습니다. 변경된 애플리케이션의 서명 발급·파일 검증 코드로 개발용 S3/CDN에 전시·작품 HEIC를 각각 업로드했습니다. PUT·HEAD, CDN 원본 바이트와 MIME, Range 206, CORS를 확인했습니다. 생성한 객체 2개는 삭제 후 404와 잔여 0개를 확인했습니다.

이 검증은 로컬 변경 코드와 실제 개발 저장소의 연결 검사입니다. 배포된 HTTP API나 프론트 화면 검증은 아닙니다. HEIC 변환과 모든 클라이언트에서의 렌더링을 보장하지 않습니다.

## 연동 시 확인할 사항

- FE는 `UX_UI`와 신규 12개 코드를 사용하되 과거 분야 표시를 유지합니다.
- 좋아요순 다음 페이지는 ID와 좋아요 수 커서를 함께 보냅니다. 조회 사이 좋아요가 변하는 경우 스냅샷을 보장하지 않습니다.
- 빈 섹션 생성은 FE 전환까지 유지합니다. 사진 포함 생성으로 전환 후 별도 정책 변경이 필요합니다.
- 과거 최초 공개 시각은 정확한 이력이 없어 생성 시각으로 근사했습니다.
- 추천은 적격 작품 전체의 순위를 계산합니다. 반환 ID와 추가 엔티티 조회만 최대 10개로 제한하며 부하 성능을 측정한 결과는 아닙니다.
- 실제 프론트의 카드 크롭 표시, HEIC 렌더링, 배포된 API 연동은 이번 백엔드 검증에 포함하지 않았습니다.
